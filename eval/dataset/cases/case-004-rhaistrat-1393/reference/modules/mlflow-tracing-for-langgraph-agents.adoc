= MLflow tracing for LangGraph agents

[role="_abstract"]
You can enable MLflow tracing to inspect LLM calls, tool invocations, and agent execution flows during development and in production.
Tracing helps you debug agent behavior and optimize performance by capturing a structured hierarchy of execution spans.

[NOTE]
====
MLflow tracing integration for LangGraph agents is planned for a future release of {product-name}.
Verify the target release version with your release team before including these modules in production documentation.
====

[discrete]
== How tracing works

Each LangGraph agent template includes a `tracing.py` module that integrates with MLflow.
When `MLFLOW_TRACKING_URI` is set in the `.env` file, the agent enables tracing at startup by calling `mlflow.langchain.autolog()`.
This automatically captures all LLM calls, tool executions, and agent orchestration steps without requiring manual instrumentation in your agent code.

The tracing module runs during the FastAPI lifespan startup and performs the following steps:

. Checks whether `MLFLOW_TRACKING_URI` is set. If not, tracing is silently disabled.
. Health-checks the MLflow server with retry logic (configurable via `MLFLOW_HEALTH_CHECK_TIMEOUT`).
. Configures MLflow with the tracking URI and experiment name.
. Enables `mlflow.langchain.autolog()`, which captures all LangGraph execution spans automatically.

[discrete]
== Tracing layers

MLflow captures three layers of execution for each agent request:

Agent orchestration::
The top-level LangGraph chain, including the agent's reasoning loop and conditional routing decisions.

Tool execution::
Each tool call made by the agent, including the tool name, input arguments, and return value.

LLM calls::
Each call to the `ChatOpenAI` model, including the prompt messages and the model's response.

All three layers are captured automatically by `mlflow.langchain.autolog()` for LangGraph agents.
No manual wrapping or instrumentation is required.

[discrete]
== Opt-in design

MLflow tracing is entirely opt-in.
The `MLFLOW_TRACKING_URI` environment variable is the single switch that controls whether tracing is active.

* If `MLFLOW_TRACKING_URI` is not set, the agent runs without any MLflow dependency. No MLflow packages are imported.
* If `MLFLOW_TRACKING_URI` is set but the MLflow server is unreachable at startup, the agent logs a warning and continues running without tracing.
* If `MLFLOW_TRACKING_URI` is set and the server is reachable, tracing is fully enabled.

MLflow is listed as an optional dependency under the `[tracing]` extra in each agent's `pyproject.toml`.
When `MLFLOW_TRACKING_URI` is set, the `make run-app` target automatically installs the tracing dependencies by using `uv run --extra tracing`.

[discrete]
== Graceful degradation

The tracing system does not prevent the agent from starting, even if the MLflow server is unavailable.
If the health check fails after the configured timeout, the agent logs a warning and starts without tracing.
This ensures production agents continue serving requests even if the observability infrastructure has an outage.
