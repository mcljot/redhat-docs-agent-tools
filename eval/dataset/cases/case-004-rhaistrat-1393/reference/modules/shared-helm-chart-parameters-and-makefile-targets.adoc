= Shared Helm chart parameters and Makefile targets

[role="_abstract"]
All LangGraph agent templates share a common Helm chart and a standardized set of Makefile targets.
You use the Makefile targets to manage the complete agent lifecycle from initialization through deployment, and you customize deployments by overriding Helm chart parameters.

[discrete]
== Makefile targets

Run all Makefile targets from within the agent directory (for example, `agents/langgraph/react_agent/`).

.Available Makefile targets
[cols="2,3,2", options="header"]
|===
|Target
|Description
|Prerequisites

|`make init`
|Creates a `.env` file from `.env.example`.
|None

|`make env`
|Creates a Python virtual environment and installs dependencies with `uv`.
|`uv` installed

|`make run-app`
|Starts the agent locally with hot-reload on port 8000 with the web playground UI. Auto-installs the `[tracing]` extra if `MLFLOW_TRACKING_URI` is set.
|`.env` configured

|`make run-app-fresh`
|Kills any existing process on the agent port and starts the agent's FastAPI server with hot-reload. Use when port 8000 is already in use.
|`.env` configured

|`make run-cli`
|Starts an interactive CLI session for terminal-based testing.
|`.env` configured

|`make ollama`
|Starts a local Ollama server.
|Ollama installed

|`make llama-server`
|Starts a local Llama Stack server.
|`uv` installed

|`make re-init`
|Activates the Python virtual environment and reloads `.env` variables into the shell session.
|`.env` configured, `make env` completed

|`make test`
|Runs the agent's test suite with `pytest`.
|`make env`

|`make build`
|Builds the container image locally using Podman or Docker. Auto-detects the container runtime, preferring Podman.
|Podman or Docker installed

|`make push`
|Pushes the built image to the container registry specified in `CONTAINER_IMAGE`.
|`make build`, registry login

|`make build-openshift`
|Builds the container image in-cluster using an OpenShift `BuildConfig`. No local container runtime or registry account needed.
|`oc` CLI, logged in to OpenShift

|`make deploy`
|Deploys the agent to OpenShift using `helm upgrade --install`. Passes `.env` values as Helm overrides and stores secrets in a temporary file that is cleaned up after deployment.
|`oc` CLI, Helm 3, `CONTAINER_IMAGE` set

|`make dry-run`
|Previews the rendered Helm manifests without deploying. Secrets are redacted in the output.
|`.env` configured

|`make undeploy`
|Removes the agent deployment from OpenShift using `helm uninstall`.
|`oc` CLI, Helm 3

|`make help`
|Lists all available Makefile targets with descriptions.
|None
|===

[discrete]
== agent.yaml metadata schema

Each agent directory contains an `agent.yaml` file that defines the agent's metadata and required environment variables.
The Makefile reads this file at runtime to validate that all required variables are set before deployment.

.agent.yaml fields
[cols="2,1,3", options="header"]
|===
|Field
|Type
|Description

|`name`
|String
|Machine-readable agent name used as the Helm release name and Kubernetes resource name. Example: `langgraph-react-agent`.

|`displayName`
|String
|Human-readable agent name. Example: `LangGraph ReAct Agent`.

|`framework`
|String
|Agent framework identifier. Example: `langgraph`.

|`description`
|String
|Short description of the agent's purpose.

|`env.required`
|List
|Environment variables that must be set before deployment. The Makefile validates these and fails with a clear error if any are missing.

|`env.optional`
|List
|Environment variables that can be set but are not required.
|===

[discrete]
== Helm chart values

All agents share the Helm chart at `charts/agent/`.
Each agent has a `values.yaml` file that overrides the shared chart defaults.
You can further override values at deploy time with `--set` flags.

The override chain is:

. `charts/agent/values.yaml` -- global defaults for all agents
. Agent-specific `values.yaml` -- per-agent overrides (for example, `agents/langgraph/react_agent/values.yaml`)
. `--set` flags -- CLI overrides at deploy time

.Helm chart parameters
[cols="2,1,1,3", options="header"]
|===
|Parameter
|Type
|Default
|Description

|`replicaCount`
|Integer
|`1`
|Number of pod replicas.

|`image.repository`
|String
|None (required)
|Container image repository. Set via `CONTAINER_IMAGE` in `.env`.

|`image.tag`
|String
|`latest`
|Container image tag.

|`image.pullPolicy`
|String
|`Always`
|Kubernetes image pull policy.

|`env`
|Map
|`{}`
|Environment variables to set on the container. Agent-specific `values.yaml` files populate this map.

|`secrets.apiKey`
|String
|None
|API key stored as a Kubernetes Secret and injected as the `API_KEY` environment variable.

|`secrets.postgresPassword`
|String
|None
|PostgreSQL password stored as a Kubernetes Secret and injected as `POSTGRES_PASSWORD`.

|`secrets.mlflowTrackingToken`
|String
|None
|MLflow authentication token stored as a Kubernetes Secret and injected as `MLFLOW_TRACKING_TOKEN`.

|`extraSecrets`
|Map
|`{}`
|Additional key-value pairs stored as Kubernetes Secrets and injected as environment variables. Keys must follow POSIX naming conventions.

|`service.port`
|Integer
|`8080`
|Port exposed by the Kubernetes Service. Also set as the `PORT` environment variable in the container.

|`service.type`
|String
|`ClusterIP`
|Kubernetes Service type.

|`resources.requests.memory`
|String
|`256Mi`
|Minimum memory request for the container.

|`resources.requests.cpu`
|String
|`100m`
|Minimum CPU request for the container.

|`resources.limits.memory`
|String
|`512Mi`
|Maximum memory limit for the container.

|`resources.limits.cpu`
|String
|`500m`
|Maximum CPU limit for the container.

|`openshift.route.enabled`
|Boolean
|`true`
|Whether to create an OpenShift Route for external access.

|`openshift.route.tls.termination`
|String
|`edge`
|TLS termination policy for the OpenShift Route.

|`ingress.enabled`
|Boolean
|`false`
|Whether to create a Kubernetes Ingress instead of an OpenShift Route.

|`ingress.host`
|String
|None
|Hostname for the Kubernetes Ingress.

|`healthCheck.path`
|String
|`/health`
|Path for liveness and readiness probes.

|`healthCheck.livenessInitialDelay`
|Integer
|`10`
|Number of seconds after container startup before the liveness probe is initiated.

|`healthCheck.livenessPeriod`
|Integer
|`120`
|Number of seconds between liveness probe checks.

|`healthCheck.livenessTimeout`
|Integer
|`5`
|Number of seconds after which the liveness probe times out.

|`healthCheck.readinessInitialDelay`
|Integer
|`5`
|Number of seconds after container startup before the readiness probe is initiated.

|`healthCheck.readinessPeriod`
|Integer
|`30`
|Number of seconds between readiness probe checks.

|`healthCheck.readinessTimeout`
|Integer
|`3`
|Number of seconds after which the readiness probe times out.

|`volumes`
|List
|`[]`
|Additional volumes to mount in the pod.

|`volumeMounts`
|List
|`[]`
|Mount points for additional volumes.
|===

[discrete]
== Kubernetes resources created by the Helm chart

When you run `make deploy`, the shared Helm chart creates the following Kubernetes resources.

.Kubernetes resources
[cols="1,1,3", options="header"]
|===
|Resource
|API version
|Description

|Deployment
|`apps/v1`
|Runs the agent container with the configured environment variables, resource limits, and health check probes. The container runs as non-root (`runAsNonRoot: true`) with restricted security context.

|Service
|`v1`
|Exposes the agent on port 8080 within the cluster using `ClusterIP` type by default.

|Route
|`route.openshift.io/v1`
|Creates an OpenShift Route with edge TLS termination for external HTTPS access. Enabled by default; disable with `openshift.route.enabled=false`.

|Secret
|`v1`
|Stores sensitive values (`API_KEY`, `POSTGRES_PASSWORD`, `MLFLOW_TRACKING_TOKEN`, and any `extraSecrets`) as base64-encoded data. Only created if at least one secret value is set.
|===
