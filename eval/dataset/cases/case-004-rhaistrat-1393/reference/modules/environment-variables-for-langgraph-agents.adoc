= Environment variables for LangGraph agents

[role="_abstract"]
You configure LangGraph agents by setting environment variables in the `.env` file.
The following tables list all available environment variables across the four agent templates, including which agents use each variable and the default values.

Each agent directory contains an `.env.example` file with all supported variables.
Run `make init` to create a `.env` file from this template.

[discrete]
== Core environment variables

The following environment variables are required or commonly used by all LangGraph agent templates.

.Core environment variables
[cols="2,1,1,1,3", options="header"]
|===
|Variable
|Required
|Agents
|Default
|Description

|`API_KEY`
|Yes
|All
|`not-needed-for-local-development` (placeholder in `.env.example`)
|API key for the model serving endpoint. Not required when `BASE_URL` points to `localhost` or `127.0.0.1`.

|`BASE_URL`
|Yes
|All
|`http://localhost:8321/v1`
|Base URL of the OpenAI-compatible model serving endpoint. The agent appends `/v1` automatically if the URL does not already end with it.

|`MODEL_ID`
|Yes
|All
|`ollama/llama3.1:8b`
|Model identifier to use for inference. Must match a model available on the endpoint specified by `BASE_URL`. The `ollama/` prefix in the default value is required when using Llama Stack as a proxy. When connecting directly to Ollama, omit the prefix (for example, `llama3.2:3b`).

|`PORT`
|No
|All
|`8000`
|Port on which the agent's FastAPI server listens. Inside containers, this is set to `8080` by the Helm chart.

|`CONTAINER_IMAGE`
|No
|All
|None
|Full container image path for deployment. Format: `<registry>/<namespace>/<image-name>:<tag>`. Required for `make build`, `make push`, and `make deploy`.
|===

[discrete]
== RAG-specific environment variables

The following environment variables apply only to the Agentic RAG agent.

.Agentic RAG environment variables
[cols="2,1,1,3", options="header"]
|===
|Variable
|Required
|Default
|Description

|`EMBEDDING_MODEL`
|No
|None
|Model identifier for generating document embeddings. If not set, the agent uses its configured default.

|`EMBEDDING_DIMENSION`
|No
|`768`
|Dimensionality of embedding vectors. Must match the output dimension of the embedding model.

|`VECTOR_STORE_ID`
|No
|None
|Identifier for the vector store collection.

|`VECTOR_STORE_PROVIDER`
|No
|`milvus`
|Vector store backend provider. Currently supports `milvus`.

|`VECTOR_STORE_PATH`
|No
|`./data/milvus_lite.db`
|Path to the local Milvus Lite database file. Used for local development only.

|`DOCS_TO_LOAD`
|No
|`./data/sample_knowledge.txt`
|Path to documents to load into the vector store for retrieval.
|===

[discrete]
== Database memory environment variables

The following environment variables apply only to the Database Memory agent and are required when using PostgreSQL-backed conversation memory.

.Database memory environment variables
[cols="2,1,1,3", options="header"]
|===
|Variable
|Required
|Default
|Description

|`POSTGRES_HOST`
|Yes
|`localhost`
|Hostname of the PostgreSQL server.

|`POSTGRES_PORT`
|Yes
|`5432`
|Port on which PostgreSQL listens.

|`POSTGRES_DB`
|Yes
|`agent_memory`
|Name of the PostgreSQL database used for conversation history.

|`POSTGRES_USER`
|Yes
|`postgres`
|PostgreSQL username.

|`POSTGRES_PASSWORD`
|Yes
|None
|PostgreSQL password. On OpenShift, this is stored as a Kubernetes Secret and injected as an environment variable.
|===

[discrete]
== MLflow tracing environment variables

The following environment variables control MLflow tracing integration.
Tracing is optional for all agents.
If `MLFLOW_TRACKING_URI` is not set, the agent runs without any MLflow dependency.

[NOTE]
====
MLflow tracing for LangGraph agents is planned for a future release of {product-name}.
The tracing environment variables are documented here because they appear in the `.env.example` files.
====

.MLflow tracing environment variables
[cols="2,1,1,1,3", options="header"]
|===
|Variable
|Required
|Scope
|Default
|Description

|`MLFLOW_TRACKING_URI`
|No
|Local and OpenShift
|None
|URL of the MLflow tracking server. Setting this variable enables tracing.

|`MLFLOW_EXPERIMENT_NAME`
|No
|Local and OpenShift
|`default-agent-experiment`
|Name of the MLflow experiment for organizing traces.

|`MLFLOW_HEALTH_CHECK_TIMEOUT`
|No
|Local and OpenShift
|`5`
|Number of seconds to wait for the MLflow server to respond at startup.

|`MLFLOW_HTTP_REQUEST_TIMEOUT`
|No
|Local and OpenShift
|`2`
|Timeout in seconds for MLflow HTTP requests during operation. The agent templates default to `2` seconds for local development. The MLflow library default is `120` seconds.

|`MLFLOW_HTTP_REQUEST_MAX_RETRIES`
|No
|Local and OpenShift
|MLflow default
|Maximum number of retries for MLflow HTTP requests.

|`MLFLOW_TRACKING_TOKEN`
|No
|OpenShift only
|None
|Authentication token for MLflow on OpenShift, obtained from the OpenShift console.

|`MLFLOW_TRACKING_INSECURE_TLS`
|No
|OpenShift only
|None
|Set to `true` if the OpenShift cluster uses self-signed TLS certificates.

|`MLFLOW_WORKSPACE`
|No
|OpenShift only
|None
|Project or workspace name for the MLflow instance on OpenShift.

|`MLFLOW_TRACKING_AUTH`
|No
|OpenShift only
|None
|Use Kubernetes service account authentication when running inside the cluster.
|===
