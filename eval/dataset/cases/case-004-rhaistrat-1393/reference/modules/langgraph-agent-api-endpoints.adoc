= LangGraph agent API endpoints

[role="_abstract"]
All LangGraph agent templates expose an OpenAI-compatible HTTP API with a chat completions endpoint and a health check endpoint.
The Human-in-the-Loop agent extends the standard API with additional fields for the approval workflow.

[discrete]
== POST /chat/completions

Sends a message to the agent and receives a response.
Supports both non-streaming and streaming (Server-Sent Events) modes.

.Request body
[cols="2,1,1,3", options="header"]
|===
|Field
|Type
|Required
|Description

|`messages`
|Array
|Yes
|A list of messages comprising the conversation. Each message has a `role` (such as `user`, `assistant`, or `system`) and `content` (the message text).

|`stream`
|Boolean
|No
|If `true`, the response is streamed as Server-Sent Events (SSE). Each event contains a `data:` field with a JSON chunk. The stream terminates with `data: [DONE]`. Default: `false`.

|`model`
|String
|No
|ID of the model to report in the response metadata. Does not change the model used for inference, which is configured at startup via the `MODEL_ID` environment variable. Defaults to the server's configured `MODEL_ID`.

|`thread_id`
|String
|No
|Thread identifier for conversation persistence. Required for Human-in-the-Loop approval flows and for PostgreSQL-backed conversation memory. If omitted, a new thread ID is generated automatically.

|`approval`
|String
|No
|Human-in-the-Loop only. Set to `yes` to approve or `no` to reject a pending tool call. Must be sent with the same `thread_id` as the pending approval response.
|===

.Non-streaming request example
[source,terminal]
----
$ curl -X POST http://localhost:8000/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "Hello!"}], "stream": false}'
----

.Non-streaming response example
[source,json]
----
{
  "id": "chatcmpl-abc123def456",
  "object": "chat.completion",
  "created": 1716300000,
  "model": "llama3.2:3b",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": null
}
----

[NOTE]
====
Agents that support conversation persistence (Human-in-the-Loop and Database Memory) include a `thread_id` field in the response.
The basic ReAct agent and Agentic RAG agent do not include `thread_id` in responses.
====

.Streaming request example
[source,terminal]
----
$ curl -sN -X POST http://localhost:8000/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "Hello!"}], "stream": true}'
----

.Streaming response example

Each SSE event contains a JSON chunk with incremental content:

[source,text]
----
data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1716300000,"model":"llama3.2:3b","choices":[{"index":0,"delta":{"content":"Hello!"},"finish_reason":null}]}

data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1716300000,"model":"llama3.2:3b","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
----

[discrete]
== Human-in-the-Loop approval flow

The Human-in-the-Loop agent extends the standard response with additional `finish_reason` values and the `approval` request field.

.finish_reason values
[cols="1,3", options="header"]
|===
|Value
|Description

|`stop`
|The agent completed its response normally. No further action is needed.

|`pending_approval`
|The agent paused execution before calling a sensitive tool. The response `content` contains the pending tool call details as a JSON string. Send a follow-up request with `approval: "yes"` or `approval: "no"` and the same `thread_id` to resume.
|===

.Approval response example

When the agent pauses for approval, the response includes `finish_reason: "pending_approval"` and the `thread_id`:

[source,json]
----
{
  "id": "chatcmpl-abc123def456",
  "object": "chat.completion",
  "created": 1716300000,
  "model": "llama3.2:3b",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "{\"question\": \"Do you approve the following tool call(s)?\", \"tool_calls\": [\"Tool: create_file, Args: {\\\"filename\\\": \\\"report.md\\\", \\\"content\\\": \\\"...\\\"}\"], \"options\": [\"yes\", \"no\"]}"
      },
      "finish_reason": "pending_approval"
    }
  ],
  "thread_id": "conversation-1"
}
----

.Approval request example

[source,terminal]
----
$ curl -X POST http://localhost:8000/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{"role": "user", "content": ""}],
    "thread_id": "conversation-1",
    "approval": "yes"
  }'
----

[discrete]
== GET /health

Returns the current health status of the agent service.

.Response fields
[cols="2,1,3", options="header"]
|===
|Field
|Type
|Description

|`status`
|String
|`healthy` when the agent is initialized and ready to serve requests, or `not_ready` when the agent is still starting up.

|`agent_initialized`
|Boolean
|`true` when the agent graph has been compiled and is ready, `false` otherwise.
|===

.Request example
[source,terminal]
----
$ curl http://localhost:8000/health
----

.Response example
[source,json]
----
{
  "status": "healthy",
  "agent_initialized": true
}
----

[NOTE]
====
The Database Memory agent extends the health response with an additional `database_connected` field that indicates whether the PostgreSQL connection is configured.
====

When the agent is not ready, the endpoint returns HTTP status code 503 with `"status": "not_ready"`.

[discrete]
== Error responses

All endpoints return standard HTTP error codes.

.Common error responses
[cols="1,1,3", options="header"]
|===
|Status code
|Error
|Description

|`400`
|Bad Request
|The request body is invalid or missing required fields.

|`500`
|Internal Server Error
|An unexpected error occurred during request processing. Check the agent logs for details.

|`503`
|Service Unavailable
|The agent has not been initialized. This occurs during startup or if the agent failed to initialize.
|===
