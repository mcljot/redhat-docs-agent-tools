= Configure persistent agent memory with PostgreSQL

[role="_abstract"]
You can configure the Database Memory agent to persist conversation history in PostgreSQL so that conversations survive agent restarts and pod rescheduling.
The agent stores the full conversation history in PostgreSQL but sends only the most recent messages to the LLM to keep the context window manageable.

The Database Memory agent uses `AsyncPostgresSaver` from the `langgraph-checkpoint-postgres` package as its LangGraph checkpointer.
In local development without PostgreSQL, the agent falls back to `MemorySaver`, which stores state in memory only and loses conversations when the agent restarts.

[discrete]
=== How FIFO message trimming works

The agent uses a `FIFOMessageTrimmer` middleware that sends only the last 5 messages (by default) to the LLM, while PostgreSQL retains the complete conversation history.
This keeps the LLM context window small and efficient regardless of how long the conversation runs.

When trimming creates an orphaned tool message (a `ToolMessage` without its preceding `AIMessage` containing the tool call), the trimmer automatically removes it from the context to prevent LLM errors.

.Prerequisites

* The Database Memory agent is running locally. See xref:running-a-langgraph-agent-locally_{context}[Run a LangGraph agent locally].
* A PostgreSQL 14+ instance is running and accessible. You can use a managed PostgreSQL service, or run one locally.

.Procedure

. Start a local PostgreSQL instance if one is not already running.
+
Using Podman or Docker:
+
[source,terminal]
----
$ podman run --name postgres-agent \
  -e POSTGRES_PASSWORD=<your_password> \
  -e POSTGRES_DB=agent_memory \
  -p 5432:5432 \
  -d postgres:16
----
+
On macOS with Homebrew:
+
[source,terminal]
----
$ brew install postgresql@16
$ brew services start postgresql@16
$ createdb agent_memory
----

. Configure the PostgreSQL connection variables in the `.env` file:
+
[source,ini]
----
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=agent_memory
POSTGRES_USER=postgres
POSTGRES_PASSWORD=<your_password>
----

. Start the agent:
+
[source,terminal]
----
$ make run-app
----
+
The agent automatically creates the required database tables on first startup.
No manual schema setup is required.

. Send a message with a `thread_id` to start a persistent conversation:
+
[source,terminal]
----
$ curl -X POST http://localhost:8000/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{"role": "user", "content": "My name is Alice and I work at Red Hat."}],
    "stream": false,
    "thread_id": "test-conversation-1"
  }'
----

. Continue the conversation using the same `thread_id`:
+
[source,terminal]
----
$ curl -X POST http://localhost:8000/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{"role": "user", "content": "What is my name and where do I work?"}],
    "stream": false,
    "thread_id": "test-conversation-1"
  }'
----
+
The agent retrieves the conversation history from PostgreSQL and responds with information from the previous message.

. Optional: Adjust the FIFO message trimming window.
+
Edit `src/react_with_database_memory/agent.py` and change the `max_messages_in_context` value:
+
[source,python]
----
max_messages_in_context = 10  # Keep last 10 messages instead of default 5
----

.Verification

. Restart the agent and verify that conversations persist:
+
[source,terminal]
----
$ curl -X POST http://localhost:8000/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{"role": "user", "content": "Do you remember my name?"}],
    "stream": false,
    "thread_id": "test-conversation-1"
  }'
----
+
If PostgreSQL persistence is working, the agent retrieves the conversation history and responds correctly even after a restart.

. Verify the database tables were created:
+
[source,terminal]
----
$ psql -h localhost -U postgres -d agent_memory -c "\dt"
----

.Troubleshooting

* If the agent fails to start with a connection error, verify the PostgreSQL host, port, and credentials in your `.env` file. Ensure the PostgreSQL service is running and accepting connections.
* If conversations are not persisted, verify that you are including a `thread_id` in your requests. When `thread_id` is omitted, the agent runs without persistence.
