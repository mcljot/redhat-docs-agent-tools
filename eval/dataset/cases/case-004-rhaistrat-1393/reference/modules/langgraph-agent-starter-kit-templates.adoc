= LangGraph agent starter kit templates

[role="_abstract"]
You can build AI agents from proven LangGraph templates and deploy them to {product-name} without writing infrastructure code from scratch.
The agentic starter kits provide four ready-to-use agent templates that cover common agent patterns, a standardized Makefile interface, and a Helm-based deployment workflow.
You develop and test locally with Ollama, then deploy to production by changing only environment configuration.

The agentic starter kits are an open source collection of agent templates in the link:https://github.com/red-hat-data-services/agentic-starter-kits[agentic-starter-kits repository].
Each template includes a complete project structure with a `Dockerfile`, `pyproject.toml`, Makefile targets, and a web playground UI for interactive testing.
All agents expose an OpenAI-compatible API with `POST /chat/completions` and `GET /health` endpoints, so you can integrate them into existing toolchains that expect the OpenAI chat completions format.

[discrete]
== Standardized developer experience

All four agent templates share a common developer workflow:

* **Makefile interface**: Use `make init`, `make run-app`, `make build`, `make deploy`, and other targets to manage the full agent lifecycle without learning framework-specific tools.
* **Helm-based deployment**: A shared Helm chart at `charts/agent/` generates the Kubernetes resources (Deployment, Service, Route, Secret) for any agent.
* **OpenAI-compatible API**: Every agent exposes `POST /chat/completions` (with both streaming and non-streaming modes) and `GET /health`.
* **Web playground**: Each agent includes a built-in chat UI at `http://localhost:8000` for interactive testing during development.

[discrete]
== Configuration-driven provider swap

The agentic starter kits use a configuration-driven architecture that separates application logic from provider configuration.
You develop locally with one set of providers and deploy to production by changing only environment variables in the `.env` file -- no code changes are required.

All agents connect to model serving endpoints through the OpenAI-compatible `ChatOpenAI` client.
The `BASE_URL` environment variable controls which endpoint the agent uses.
Locally, this points to Ollama or a Llama Stack server.
In production, this points to a vLLM or llm-d endpoint served by an `InferenceService` on {product-name}.

The following table shows the provider mapping between local development and production deployment.

.Provider mapping for local and production environments
[cols="1,1,1", options="header"]
|===
|Service
|Local provider
|Production provider

|LLM inference
|Ollama or Llama Stack (`localhost:8321`)
|vLLM or llm-d (`InferenceService` endpoint)

|Vector database
|Milvus Lite (file-based)
|Milvus or PGVector (cluster-hosted)

|Conversation memory
|`MemorySaver` (in-memory)
|`AsyncPostgresSaver` (PostgreSQL)
|===
