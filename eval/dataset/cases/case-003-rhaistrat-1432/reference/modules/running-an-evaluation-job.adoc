= Run an evaluation job

[role="_abstract"]
You can submit an evaluation job to assess a model against one or more benchmarks.
The evaluation stack runs the benchmarks as Kubernetes jobs and reports results through the CLI, SDK, or REST API.

.Prerequisites

* The evaluation stack client tools are installed and configured. See xref:installing-the-evaluation-stack-client-tools_{context}[Install the evaluation stack client tools].
* A model endpoint is accessible from the OpenShift cluster (for example, a vLLM or OpenAI-compatible inference endpoint).

.Procedure

. Identify the provider and benchmark for your evaluation.
+
List available providers:
+
[source,terminal]
----
$ evalhub providers list
----
+
Describe a provider to see its benchmarks:
+
[source,terminal]
----
$ evalhub providers describe lm_evaluation_harness
----

. Submit an evaluation job.
+
--
You can submit a job by using a configuration file or command-line flags.

*Option 1: Using a configuration file*

Create an evaluation configuration file named `eval.yaml`:

[source,yaml]
----
name: my-evaluation
model:
  url: "http://vllm:8000/v1" <1>
  name: "meta-llama/llama-3.1-8b" <2>
benchmarks:
  - id: arc_easy <3>
    provider_id: lm_evaluation_harness <4>
    parameters:
      num_fewshot: 0
experiment:
  name: "llama-3-eval" <5>
----
<1> The URL of the model inference endpoint.
<2> The model name or identifier.
<3> The benchmark ID. Use `evalhub providers describe` to find available benchmarks.
<4> The provider that supplies the benchmark.
<5> Optional. An MLflow experiment name for tracking results.

Submit the job:

[source,terminal]
----
$ evalhub eval run --config eval.yaml
----

*Option 2: Using command-line flags*

[source,terminal]
----
$ evalhub eval run \
    --name my-evaluation \
    --model-url http://vllm:8000/v1 \
    --model-name meta-llama/llama-3.1-8b \
    --provider lm_evaluation_harness \
    -b arc_easy \
    -b hellaswag
----

*Option 3: Using the REST API*

[source,terminal]
----
$ curl -X POST "https://<evalhub_url>/api/v1/evaluations/jobs" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <token>" \
    -H "X-Tenant: <tenant_namespace>" \
    -d '{
      "name": "my-evaluation",
      "model": {
        "url": "http://vllm:8000/v1",
        "name": "meta-llama/llama-3.1-8b"
      },
      "benchmarks": [
        {
          "id": "arc_easy",
          "provider_id": "lm_evaluation_harness",
          "parameters": {"num_fewshot": 0}
        }
      ],
      "experiment": {
        "name": "llama-3-eval"
      }
    }'
----

*Option 4: Using the Python SDK*

[source,python]
----
from evalhub import (
    EvalHubClient,
    JobSubmissionRequest,
    ModelConfig,
    BenchmarkConfig,
)

with SyncEvalHubClient(
    base_url="https://evalhub.example.com",
    auth_token="<token>",
    tenant="<tenant_namespace>",
) as client:
    request = JobSubmissionRequest(
        name="my-evaluation",
        model=ModelConfig(
            url="http://vllm:8000/v1",
            name="meta-llama/llama-3.1-8b",
        ),
        benchmarks=[
            BenchmarkConfig(
                id="arc_easy",
                provider_id="lm_evaluation_harness",
                parameters={"num_fewshot": 0},
            ),
        ],
    )
    job = client.jobs.submit(request)
    print(f"Job submitted: {job.id}")
----
--

. Monitor the job status:
+
--
To check the status of a specific job:

[source,terminal]
----
$ evalhub eval status <job_id>
----

To watch a job until it completes:

[source,terminal]
----
$ evalhub eval status <job_id> --watch
----

To submit a job and wait for completion in a single command:

[source,terminal]
----
$ evalhub eval run --config eval.yaml --wait
----
--

. Retrieve the results when the job completes:
+
[source,terminal]
----
$ evalhub eval results <job_id>
----
+
To export results as JSON:
+
[source,terminal]
----
$ evalhub eval results <job_id> --format json > results.json
----

.Verification

. Verify the job completed successfully:
+
[source,terminal]
----
$ evalhub eval status <job_id>
----
+
The output shows the job state as `completed` and lists the status of each benchmark.

. Check that metrics are present in the results:
+
[source,terminal]
----
$ evalhub eval results <job_id>
----
+
The output displays a table with benchmark, provider, metric name, and metric value columns.
If MLflow tracking was configured, the output also shows the MLflow experiment URL.

== Evaluation job lifecycle states

An evaluation job transitions through the following states:

.Job lifecycle states
[cols="1,2", options="header"]
|===
|State
|Description

|`pending`
|The job has been submitted and is waiting for resources.

|`running`
|At least one benchmark in the job is actively running.

|`completed`
|All benchmarks in the job completed successfully.

|`failed`
|One or more benchmarks failed and no benchmarks completed successfully.

|`cancelled`
|The job was cancelled by a user.

|`partially_failed`
|At least one benchmark completed successfully, but one or more benchmarks failed.

|===

Individual benchmarks within a job follow the same state model without the `partially_failed` state.
A benchmark is in a terminal state when it reaches `completed`, `failed`, or `cancelled`.

[discrete]
[id="cancelling-an-evaluation-job_{context}"]
== Cancelling an evaluation job

To cancel a running or pending job:

[source,terminal]
----
$ evalhub eval cancel <job_id>
----

To permanently delete a job and its associated resources:

[source,terminal]
----
$ evalhub eval cancel <job_id> --hard-delete
----
