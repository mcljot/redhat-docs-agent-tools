= Llama Stack API provider support

[role="_abstract"]
You can use the following table to identify which API providers are available in the Llama Stack distribution image, their activation status, and how to enable them.
Providers are categorized as enabled by default, environment-variable-activated, or dependency-only.

[discrete]
== Provider status categories

Enabled by default:: The provider is included in the default `config.yaml` and activates at server startup without additional configuration.

Environment-variable-activated:: The provider is included in the default `config.yaml` but only activates when you set the specified environment variable.

Dependency only:: The provider's Python dependencies are pre-installed in the container image, but the provider definition is not included in the default `config.yaml`. To use a dependency-only provider, you must supply a custom `config.yaml` at runtime. For instructions, see xref:re-enabling-inline-providers-custom-config_{context}[].

^[1]^ Dependency-only providers are not included in the default runtime `config.yaml` but their Python dependencies are pre-installed in the container image.
To use them, supply a custom `config.yaml` at runtime that includes the provider definitions from the `build.yaml` manifest.
In a future release, the Python dependencies for dependency-only providers will be fully removed from the container image.

[discrete]
== Migration mapping for removed inline providers

If you used inline providers that are now dependency-only, the following table shows the recommended remote provider replacements for production deployments:

.Inline to remote provider migration
[cols="1,1,1", options="header"]
|===
|Removed inline provider
|Recommended remote replacement
|Notes

|`inline::sentence-transformers`
|`remote::vllm` (with `VLLM_EMBEDDING_URL`)
|Default embedding model: `ibm-granite/granite-embedding-125m-english`

|`inline::milvus`
|`remote::milvus` (with `MILVUS_ENDPOINT`)
|Remote Milvus supports multi-worker deployments.

|`inline::faiss`
|`remote::pgvector` (with `ENABLE_PGVECTOR`) or `remote::qdrant` (with `ENABLE_QDRANT`)
|Choose based on your existing database infrastructure.
|===
