= Deprecated functionality: Inline provider toggles removed from default Llama Stack configuration

[role="_abstract"]
Starting with {product-name} {product-version}, the inline providers `inline::sentence-transformers`, `inline::milvus`, and `inline::faiss` are no longer included in the default runtime configuration (`config.yaml`) of the Llama Stack distribution image.
This change affects users who enabled these providers by using environment variables in `LlamaStackDistribution` custom resources or container configurations.

[discrete]
== What changed

The following inline providers have been removed from the default runtime configuration:

* `inline::sentence-transformers` -- local embedding inference provider
* `inline::milvus` -- local Milvus vector database provider
* `inline::faiss` -- local Facebook AI Similarity Search (FAISS) vector store provider

The `ENABLE_SENTENCE_TRANSFORMERS`, `ENABLE_INLINE_MILVUS`, and `ENABLE_FAISS` environment variables are no longer functional.
Setting these environment variables in your `LlamaStackDistribution` custom resource or container configuration has no effect.

The Python dependencies for these providers remain pre-installed in the container image for this release.
In a future release, the dependencies will be fully removed from the image.

[discrete]
== What is not affected

The `inline::localfs` provider is not deprecated and remains enabled by default.
The `inline::localfs` provider is a runtime dependency of the `inline::file-search` tool provider, which powers built-in retrieval-augmented generation (RAG) file search functionality.

The following inline providers also remain in the default configuration and are not affected:

* `inline::builtin` (responses API)
* `inline::file-search` (RAG tool runtime)
* `inline::pypdf` (PDF file processing)
* `inline::reference` (batches API)

[discrete]
== Migration options

You have two options to address this change:

.Recommended: Migrate to remote providers
Replace the removed inline providers with their remote equivalents for production deployments.

.Migration mapping
[cols="1,1,1", options="header"]
|===
|Removed inline provider
|Recommended remote replacement
|Purpose

|`inline::sentence-transformers`
|`remote::vllm` (with `VLLM_EMBEDDING_URL`)
|Embedding inference

|`inline::milvus`
|`remote::milvus` (with `MILVUS_ENDPOINT`)
|Vector storage

|`inline::faiss`
|`remote::pgvector` (with `ENABLE_PGVECTOR`) or `remote::qdrant` (with `ENABLE_QDRANT`)
|Vector storage
|===

For the default embedding model configuration, the distribution image uses `ibm-granite/granite-embedding-125m-english` with the `remote::vllm` embedding provider.

.Temporary workaround: Re-enable inline providers
If you need to continue using inline providers, you can supply a custom `config.yaml` at runtime that includes the provider definitions from the `build.yaml` manifest.
This workaround is available for this release because the Python dependencies remain pre-installed in the container image.

For instructions, see xref:re-enabling-inline-providers-custom-config_{context}[].

[discrete]
== Actions required

. Audit your existing `LlamaStackDistribution` custom resources and container configurations for references to `ENABLE_SENTENCE_TRANSFORMERS`, `ENABLE_INLINE_MILVUS`, or `ENABLE_FAISS`.
. Remove these environment variable references from your configurations.
. Choose a migration path: migrate to remote providers (recommended) or re-enable inline providers using a custom `config.yaml` (temporary).
