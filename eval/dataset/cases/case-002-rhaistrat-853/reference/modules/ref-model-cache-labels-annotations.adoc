= Model cache labels and annotations

[role="_abstract"]
The model cache feature applies labels and annotations to `InferenceService` and `LLMInferenceService` resources to track cached model associations.
You can use this reference to understand the labels and annotations that appear on your resources and to configure user-settable annotations.

[discrete]
== System-managed labels

The following labels are automatically applied by the mutating webhook when an inference service's `storageUri` matches a cached model.
Do not modify these labels manually.

.System-managed labels
[cols="2,1,3", options="header"]
|===
|Label
|Applied to
|Description

|`internal.serving.kserve.io/localmodel`
|`InferenceService`, `LLMInferenceService`
|Set to the name of the matching `LocalModelCache` resource. Indicates that the inference service is using a cluster-scoped cached model.

|`internal.serving.kserve.io/localmodel-namespace`
|`InferenceService`, `LLMInferenceService`
|Set to the namespace of the matching `LocalModelNamespaceCache` resource. Indicates that the inference service is using a namespace-scoped cached model.
|===

[discrete]
== System-managed annotations

The following annotations are automatically applied by the mutating webhook.
Do not modify these annotations manually.

.System-managed annotations
[cols="2,1,3", options="header"]
|===
|Annotation
|Applied to
|Description

|`internal.serving.kserve.io/localmodel-sourceuri`
|`InferenceService`, `LLMInferenceService`
|The `sourceModelUri` of the cached model. Used internally to track which cache resource provides the model.

|`internal.serving.kserve.io/localmodel-pvc-name`
|`InferenceService`, `LLMInferenceService`
|The name of the PVC that provides the cached model volume. The inference service pod mounts this PVC instead of downloading the model at startup.
|===

[discrete]
== User-settable annotations

You can set the following annotations on your `InferenceService` or `LLMInferenceService` resources to control model caching behavior.

.User-settable annotations
[cols="2,1,1,3", options="header"]
|===
|Annotation
|Applied to
|Value
|Description

|`serving.kserve.io/disable-localmodel`
|`InferenceService`, `LLMInferenceService`
|`"true"`
|Disables automatic model caching for this specific inference service. When set to `"true"`, the mutating webhook does not inject cached model references, and the inference service downloads the model from the remote registry at startup.

|`serving.kserve.io/nodegroup`
|`InferenceService`, `LLMInferenceService`
|Node group name (for example, `"gpu-group-1"`)
|Specifies which `LocalModelNodeGroup` to use for this inference service. Useful when multiple node groups exist and you want to direct a specific inference service to a particular group.
|===

[discrete]
== Usage examples

.Disable model caching for a specific inference service
[source,yaml]
----
apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: llama-3-8b-no-cache
  annotations:
    serving.kserve.io/disable-localmodel: "true"
spec:
  predictor:
    model:
      modelFormat:
        name: vllm
      runtime: vllm-runtime
      storageUri: "hf://meta-llama/Meta-Llama-3-8B-Instruct"
----

.Target a specific node group
[source,yaml]
----
apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: llama-3-8b
  annotations:
    serving.kserve.io/nodegroup: "gpu-group-1"
spec:
  predictor:
    model:
      modelFormat:
        name: vllm
      runtime: vllm-runtime
      storageUri: "hf://meta-llama/Meta-Llama-3-8B-Instruct"
----

.Verify model cache labels on an inference service
[source,terminal]
----
$ oc get inferenceservice llama-3-8b -o jsonpath='{.metadata.labels}' | python3 -m json.tool
----

.Example output
[source,json]
----
{
    "internal.serving.kserve.io/localmodel": "llama-3-8b-cache"
}
----
